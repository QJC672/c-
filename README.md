# ROS 通信机制模拟器（C++ 大作业）

用 C++17 从零实现一套简化版的 ROS（Robot Operating System）核心通信机制：**发布 / 订阅（Publish-Subscribe）**。
没有依赖任何第三方库，只用标准库手写消息载体、节点抽象、单例中枢、注册表路由、日志与异常体系。

## 一、功能点

| 需求 | 说明 | 状态 |
| --- | --- | --- |
| 消息载体 | `Message` 携带内容与自动生成的本地时间戳，构造后不可修改 | 已实现 |
| 节点抽象 | `Node` 为抽象基类，`Init` / `Shutdown` 纯虚，禁止实例化 | 已实现 |
| 发布者 | `Publisher` 按话题发布消息，支持字符串与自定义消息两种入口 | 已实现 |
| 订阅者 | `Subscriber` 用 `std::function` 回调接收消息，同一话题可多订阅 | 已实现 |
| 中枢 | `ROS` 单例维护「话题 → 节点列表」两张注册表并负责路由 | 已实现 |
| 多对多 | 一个话题支持多个发布者与多个订阅者，同步广播 | 已实现 |
| 异常处理 | 四层自定义异常体系，空名 / 空内容 / 重复注册全部拦截 | 已实现 |
| 日志 | 分级日志（INFO / WARN / ERROR），控制台与 `run.log` 双写（加分项 10.1、10.2） | 已实现 |
| 自定义消息 | `TemperatureMessage` 派生自 `Message`，携带结构化温度值（加分项 10.3） | 已实现 |

## 三、环境要求

- Windows 10 / 11
- Visual Studio 2022（需勾选「使用 C++ 的桌面开发」工作负载）
- C++ 语言标准：C++17（项目属性已配置）

## 四、编译与运行

1. 双击 `RosSimulator/RosSimulator.slnx` 打开解决方案。
2. 在工具栏把配置切到 `Debug` + `x64`。
3. 按 `F5`（调试运行）或 `Ctrl+F5`（不调试运行）。

程序会在当前工作目录生成 `run.log`，追加写入，多次运行不会覆盖。

## 五、预期输出

```
[INFO ] 2026-11-18 14:00:12 温度显示器A 订阅了 sensor/temperature
[INFO ] 2026-11-18 14:00:12 温度传感器 发布话题 sensor/temperature
[INFO ] 2026-11-18 14:00:12 温度传感器 发布 -> sensor/temperature : 21.1 C
[INFO ] 2026-11-18 14:00:12 [2026-11-18 14:00:12] 温度显示器A 收到: 21.1 C
    -> 显示器A 处理: 21.1 C (正常)
[INFO ] 2026-11-18 14:00:12 [2026-11-18 14:00:12] 温度记录器B 收到: 21.1 C
    -> 记录器B 存档: 21.1 C
...
[WARN ] 2026-11-18 14:00:14 话题 sensor/pressure 暂无订阅者，消息丢弃: 1013 hPa
===== 异常处理演示 =====
[ERROR] 2026-11-18 14:00:14 已拦截 -> 节点名不能为空
[ERROR] 2026-11-18 14:00:14 已拦截 -> 消息内容不能为空
[ERROR] 2026-11-18 14:00:14 已拦截 -> 同一发布者不能重复注册同一话题
[INFO ] 2026-11-18 14:00:14 中枢已关闭，注册表已清空
```

`[WARN ]` 那一行是刻意构造的：气压传感器发布了消息，但没有订阅者，中枢告警后丢弃。
末尾三行 `[ERROR]` 是异常演示：空节点名、空消息内容、重复注册，全部被捕获而不是让程序崩溃。

## 六、设计要点速览

- **单例**：Meyers Singleton（函数内 `static` 对象），拷贝构造与赋值 `= delete`，构造析构私有。
- **注册表**：`std::map<std::string, std::vector<Publisher*>>` + 同构的订阅者表，一键多值。
- **解耦**：`ROS.h` 用前置声明确认「指针不需要完整定义」，真实 `#include` 放在 `ROS.cpp`，避免循环包含。
- **消息不可变**：字段全私有、只给 `const` 引用读取、时间戳在构造时定格。
- **回调注入**：`std::function<void(const Message&)>`，一个 `Subscriber` 类承载任意处理逻辑。
- **多态消息**：`TemperatureMessage` 派生自 `Message`，订阅者用 `dynamic_cast` 判断能否取到结构化数据。
- **日志**：单例 + `std::ios::app` 追加 + 每次 `flush()`，防止异常退出丢日志。

更详细的取舍理由见 [`docs/技术文档.md`](docs/技术文档.md)。

## 八、说明

本项目为课程大作业，核心设计思路参考了 ROS 1 的 Master / Node / Publisher / Subscriber 模型，
实现上做了大幅简化：注册表在进程内、消息派发为同步直调、无线程与网络传输。
与真实 ROS 的逐项对照见 [技术文档 第八章](docs/技术文档.md)。
