# C++ 模拟 ROS 系统【需求文档】

## 1. 作业背景
>ROS（Robot Operating System）是机器人领域主流的分布式通信框架，其核心机制是「节点（Node）之间通过话题（Topic）以发布/订阅方式异步传递消息（Message）」。

## 2. 术语
| 术语| 说明 |
|------|------|
| `节点（Node）`| 系统中的一个独立进程，可以发布或订阅话题。 |
| `话题（Topic）` | 节点之间通信的通道，发布者将消息发送到特定话题，订阅者接收该话题上的消息。 |
| `发布者（Publisher）` | 向特定话题发布消息的节点。 |
| `订阅者（Subscriber）` | 接收特定话题上消息的节点。 |
| `消息（Message）` | 在节点之间传递的数据单元。 |
| `ROS(核心)` | 负责管理节点、话题、发布者和订阅者的单例类，提供注册和消息转发功能。 |

## 3. 功能需求
- **1. 消息封装**：系统应提供 Message 类，封装一条消息的内容与生成时间戳；时间戳在消息创建时自动生成，格式为 YYYY-MM-DD HH:MM:SS；消息内容对外只读。
- **2. 节点抽象**：系统应提供 Node 抽象基类，包含唯一节点名属性、只读的名称访问接口，以及初始化 Init() 和关闭 Shutdown() 两个纯虚接口；派生类必须实现这两个接口；基类析构函数必须为虚函数。
- **3. 核心注册表**：系统应提供 ROS 核心类，且全局仅存在唯一实例（单例），禁止拷贝与赋值；核心内部维护「话题名 → 发布者集合」与「话题名 → 订阅者集合」两张映射表。
- **4. 节点注册**：发布者与订阅者初始化时，应向核心注册自身所绑定的节点名与话题名；注册信息需支持同一话题存在多个发布者和多个订阅者。
- **5. 消息转发**：发布者调用发布接口时，核心应依据话题名查找到该话题下的全部订阅者，并将消息逐一投递给它们；同一话题下的多个订阅者都应收到同一条消息；不同话题之间的消息不得相互串扰。
- **6. 订阅回调**：订阅者收到消息后，应输出消息内容与时间戳日志，并调用调用方注册的回调函数处理该消息；未设置回调时不应崩溃。
- **7. 生命周期管理**：系统应提供全局关闭接口，按统一顺序关闭所有已注册节点并清空注册表；程序结束时不得残留未释放的资源。
- **8. 演示程序**：主程序应至少创建 2 个发布者与 3 个订阅者，覆盖「多对一」「一对多」两种通信关系，循环发布若干条模拟传感器数据，直观展示消息的分发效果。
- **9. 异常处理**：系统应对以下非法输入给出明确提示且不导致程序崩溃：节点名为空、重复注册、消息内容为空、向未注册的话题发布消息。异常信息应具备可读性，能够指明错误类型与出错对象。

## 4. 非功能需求
- **代码质量**：代码需遵循严格C++编码习惯。
- **文档编写**：开发前编写相应需求文档和架构设计文档，开发完成后编写相应技术文档和用户手册。
- **测试覆盖**：进行测试，测试时编写结构化测试用例，要覆盖正常场景，边界场景，异常场景。

## 5. 加分选项
- **自定义消息类型**：可选扩展自定义消息类型，如包含温度、湿度、时间戳的传感器消息。
- **同步请求-响应通信**：提供服务端/客户端同步请求，客户端发送请求后等待响应，提供超时保护，超时抛出明确异常。
- **运行时动态增删节点**：支持运行时动态添加或删除节点。
- **日志持久化**：将所有消息收发日志持久化写入文本文件。
- **自定义异常类体系**：全局自定义异常处理机制包括自定义异常类，如 NodeException，TopicException，MessageException。
- **全局异常捕获器**：全局异常捕获器，能够捕获所有未处理的异常，并将异常信息输出到日志文件中。
- **异常日志输出**：异常日志输出控制台和文件，实现异常的分级处理，并且分类输出异常日志。
