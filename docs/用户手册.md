# RosSimulator 用户手册

## 1. 这是什么

RosSimulator 是一个用 C++ 模拟 ROS（机器人操作系统）核心通信机制的程序。它实现了发布/订阅模型：**发布者**向"话题"发送消息，**订阅者**接收自己感兴趣话题的消息，中间由一个全局通信中枢 `ROS` 负责登记与分发。

程序运行后，你会看到传感器发布数据、显示器和记录器接收数据、异常被安全拦截的完整过程。

## 2. 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 及以上 |
| 开发工具 | Visual Studio 2022（需安装"使用 C++ 的桌面开发"工作负载） |
| 语言标准 | C++17 |
| 其他依赖 | 无（仅使用 C++ 标准库） |

## 3. 打开项目

1. 双击 `RosSimulator\RosSimulator.slnx`（或：打开 VS → 文件 → 打开 → 项目/解决方案）
2. 若 VS 提示"项目已在 Visual Studio 外部修改"→ 点**全部重载**

## 4. 编译与运行

1. 菜单 **生成 → 重新生成解决方案**（首次或改动代码后）
2. 按 **`Ctrl + F5`**（开始执行不调试）
3. 观察控制台输出；结束后按任意键关闭窗口

> 如果遇到链接错误 `LNK1166 COMDAT 节的选择无效`，先执行 **生成 → 清理解决方案**，再重新生成。

## 5. 运行效果解读

程序按五个阶段执行，对照下表看懂每一行输出：

| 阶段 | 你会看到的 | 含义 |
|------|-----------|------|
| 订阅 | `[INFO ] ... 温度显示器A 订阅了 sensor/temperature` | 订阅者向中枢登记"我要收这个话题" |
| 发布就绪 | `[INFO ] ... 温度传感器 发布话题 sensor/temperature` | 发布者向中枢登记"我要发这个话题" |
| 收发 | `[INFO ] ... 发布 -> sensor/temperature : 21.1 C` 后跟两条"收到" | 一条消息同时发给该话题的**所有**订阅者 |
| 业务处理 | `-> 显示器A 处理: 21.1 C (正常)` | 订阅者回调里用自己的逻辑处理消息（此处演示了按温度判断是否高温） |
| 无订阅者 | `[WARN ] 话题 sensor/pressure 暂无订阅者，消息丢弃` | 没人订阅不报错，只提醒 |
| 异常拦截 | `[ERROR] 已拦截 -> 节点名不能为空` | 非法输入被异常机制捕获，**程序不崩溃** |
| 关闭 | `中枢已关闭，注册表已清空` | 所有节点统一下线 |

其中 `(正常)` / `(高温！)` 来自自定义消息类型 `TemperatureMessage`：订阅者拿到的是结构化的数值和单位，可以直接做业务判断，不需要解析字符串。

## 6. 日志文件

每次运行都会在**项目目录**（`RosSimulator.cpp` 所在文件夹）生成/追加 `run.log`：

- 内容与控制台输出完全一致，带日期时间
- **追加模式**：多次运行的记录依次累加，不会互相覆盖
- 想清空历史，删除该文件即可，下次运行自动重建

## 7. 如何扩展

### 7.1 增加一个发布者

```cpp
Publisher lightPub("光照传感器", "sensor/light");   // 名字, 话题
lightPub.Init();                                    // 向中枢报到
lightPub.Publish("500 lux");                        // 发布
```

### 7.2 增加一个订阅者

第三个参数是回调（lambda），收到消息后想干什么写在这里：

```cpp
Subscriber lightDisplay("光照显示器", "sensor/light",
    [](const Message& m) {
        std::cout << "光照: " << m.GetContent() << std::endl;
    });
lightDisplay.Init();
```

### 7.3 定义新的消息类型

项目已内置示例：`TemperatureMessage`（见 `TemperatureMessage.h`）。它继承 `Message`，在内容字符串之外携带结构化的数值与单位：

```cpp
TemperatureMessage t(21.1, "C");     // 内容自动拼装为 "21.1 C"
tempPub.Publish(t);
```

订阅者回调里用 `dynamic_cast` 取出结构化数据（参考 `main` 中显示器A 的写法）：

```cpp
if (const auto* t = dynamic_cast<const TemperatureMessage*>(&m)) {
    std::cout << t->GetValue() << " " << t->GetUnit() << std::endl;
}
```

仿照 `TemperatureMessage` 即可定义自己的消息类型（如湿度、光照），订阅者因此可以直接使用结构化数据做业务判断，而无需解析字符串。

## 8. 常见问题（FAQ）

**Q1：控制台中文是乱码？**
源文件编码和控制台代码页必须配套：源文件存为 **UTF-8 带 BOM** 时，main 里需要 `system("chcp 65001 > nul");`；源文件是 GBK/ANSI 时则**不要**加这一行。

**Q2：报 `LNK2019 无法解析的外部符号`？**
某个函数只有声明没有实现。检查对应 `.cpp` 是否存在并已加入工程。

**Q3：报 `C2259 无法实例化抽象类`？**
你直接创建了抽象类的对象（如 `Node n("x")`），或子类没有实现全部纯虚函数（`Init`/`Shutdown`）。

**Q4：报 `LNK1166 COMDAT 节的选择无效`？**
增量链接的中间产物过期。执行 **生成 → 清理解决方案 → 重新生成解决方案**。

**Q5：第二次注册同一个节点报异常？**
这是设计行为：同一节点不能重复注册同一话题。注册前确认该节点尚未 `Init()`。

**Q6：`run.log` 越来越大？**
它是追加模式的历史记录，属于正常现象。删除后下次运行自动重建。
